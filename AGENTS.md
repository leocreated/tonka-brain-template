# Agent contract for this brain

This repository is a private personal brain built from TONKA BRAIN TEMPLATE. It holds one person's working context as small Markdown records. Every agent working here (Claude Code, Codex, or any other) follows this one contract. `CLAUDE.md` only imports this file.

## 1. Orient before acting

1. If `context/setup.md` does not exist, the brain is not set up yet. When the user asks to set up (or to resume setup), read `system/setup/GUIDE.md` completely and follow it. Do not improvise another flow.
2. If the brain is set up but this clone has no `.brain/machine.json`, it is probably a new device. Suggest `node system/bin/brain.mjs join` (see `system/setup/second-device.md`).
3. Read the context files that exist: `context/profile.md`, `context/preferences.md`, `context/priorities.md`, `context/memory-policy.md`.
4. To find anything else, search `INDEX.md` or `INDEX.jsonl` first, then open only the records you need. Do not bulk-read every folder.

## 2. Memory policy

`context/memory-policy.md` says what you may save without asking. If it is missing, use `ask-first`: propose the record and write it only after the user agrees.

- Respect the sensitivity boundaries listed there. If something falls outside them, do not save it.
- Never store passwords, API keys, tokens, recovery codes, private keys, government ID numbers or full financial account numbers. Point to where a secret is kept instead.
- Your own agent may also keep memory outside this repository, under its own settings. This contract does not change those settings, and neither should you without the user asking.

## 3. Writing records

- One dated decision, lesson or papercut per file: `decisions/YYYY-MM-DD-slug.md`, `lessons/...`, `papercuts/...`.
- Use `node system/bin/brain.mjs new <type> "Title"` or copy a file from `system/templates/`. The frontmatter format is in `system/docs/record-format.md`; keep it valid (`node system/bin/brain.mjs validate`).
- Prefer editing an existing record over creating a near-duplicate.
- Finished, fixed or replaced records are archived, not deleted: `node system/bin/brain.mjs archive <path> --status <done|resolved|superseded|archived>`.
- After adding, changing or archiving records, rebuild the index: `node system/bin/brain.mjs index`. Never edit `INDEX.md` or `INDEX.jsonl` by hand.
- Product code, its tests and its development rules live in the product's own repository. Project records here link to them; they do not copy those rules.

## 4. Ownership and writes

These rules work for one agent alone and for several agents coordinated by a tool such as Orca.

- **Check before writing.** Run `git status` first. Never overwrite, revert or reformat changes you did not make in this task.
- **One owner per file per task.** If two agents could edit the same record, one of them owns it and the other proposes changes in a note or message.
- **Concurrent writers are isolated.** Parallel agents work in separate worktrees or branches. One integration owner merges their work.
- **Generated files have one writer.** `INDEX.md`, `INDEX.jsonl` and `system/template-manifest.json` are regenerated by the integration owner after merging, never merged by hand.
- **Stage only what you own.** Never sweep another session's work into your commit.
- **Handoffs are explicit.** When work moves to another agent or device, say what is done, what is not, and who owns it now. Record a short handoff note if it will matter later.

## 5. Things you never do automatically

- Commit, push, publish, or open pull requests. Prepare the change and let the user decide, unless they asked you to commit in this session.
- Change global or user-level configuration of git, your agent, or any other tool. Per-clone setup (the TONKA hook) happens only through `node system/bin/brain.mjs hooks install` after the user agrees.
- Enable schedules, background services or automations. The optional integrations in `system/setup/integrations.md` are each chosen separately by the user.
- Bypass the privacy guard (`git commit --no-verify`) or write personal records while the repository is not proven or attested private.

## 6. Template-owned files

`system/`, the root documents and the agent adapters come from the template and are listed in `system/template-manifest.json`. The user may edit them; template updates then treat them as conflicts and keep the user's version. Records in the compartment folders always belong to the user and are never touched by updates.

## 7. Quick reference

| Task | Command |
| --- | --- |
| Setup progress and next step | `node system/bin/brain.mjs setup status` |
| Health of this clone | `node system/bin/brain.mjs doctor` |
| Rebuild or check the index | `node system/bin/brain.mjs index` / `index --check` |
| Check records | `node system/bin/brain.mjs check` |
| New record | `node system/bin/brain.mjs new decision "Title"` |
| Archive a record | `node system/bin/brain.mjs archive decisions/2026-01-01-x.md --status superseded` |
| Scan staged files for secrets | `node system/bin/brain.mjs guard` |
